# Liquidity Arena intelligent contracts

Liquidity Arena now targets V8 on GenLayer Testnet Bradbury. V8 is the only contract version that
may be selected by the application, server, history service, keeper, or deployment tooling.

## V8 source artifacts

- [`LiquidityArenaV8.py`](LiquidityArenaV8.py) is the readable reviewed source.
- [`LiquidityArenaV8.release.py`](LiquidityArenaV8.release.py) is the deterministic deployment
  artifact generated by [`../scripts/build-v8-release.py`](../scripts/build-v8-release.py).
- [`evm/LiquidityArenaPayoutFactory.sol`](evm/LiquidityArenaPayoutFactory.sol) and
  [`evm/LiquidityArenaPayoutVault.sol`](evm/LiquidityArenaPayoutVault.sol) implement the immutable
  Bradbury EVM payout escrow.

Never edit the release artifact directly. Rebuild it with Python 3.13 and the pinned
`python-minifier==3.2.0`, then require:

```text
python -X utf8 scripts/build-v8-release.py --check
python -X utf8 -m genvm_linter.cli check contracts/LiquidityArenaV8.py
python -X utf8 -m genvm_linter.cli check contracts/LiquidityArenaV8.release.py
python -X utf8 -m pytest tests/direct/test_liquidity_arena_v8.py -q
```

The current deployment artifact is 44,125 UTF-8 bytes with SHA-256
`160965bc42b34dce42fa7154923116f21edb39a7a42abc61bde162db8e15d5aa`. Its exhaustive Bradbury
schema contains 25 methods (9 views and 16 writes) and hashes to
`c8545eea9398fa05c29edf719250402f2ffda99a98ad706ffd329e457d2d89c4`.

## Bradbury payout trust anchor

V8 accepts payout activation only on chain ID 4221 and only through the compiled factory address
`0x944FdADd826C2a159c63cB100DB174716ccd1317`. That factory was deployed as a zero-value CREATE,
finalized, byte-matched, and source-verified before its address was frozen into V8. V8 is now
finalized at `0xe6aa95e551f8407b139474ec60c2012e4cc8a6cd`, and the factory's one-time binding to that exact
arena is finalized. Reserve funding, payout activation, risk resume, canary, and production cutover
remain pending, so the deployment manifest stays inactive.

Player and treasury payouts use this state machine:

```text
PREPARING -> DISPATCHED -> FUNDED_IN_ESCROW -> EOA_WITHDRAWN
```

The intelligent contract never treats an emitted cross-layer transfer as final delivery. It
reserves three exact attempts, sends only to the deterministic immutable vault, confirms exact
factory credit, and records the final wallet claim only after the recipient's EVM withdrawal is
proven. Duplicate or late sends become recoverable excess and cannot be credited twice.

Payout activation deliberately leaves `new_risk_enabled=false`. New epochs and wagers open only
after an attended payout/risk canary and the separate owner-only `resume_new_risk()` call.

## Market policy

- Assets: BTC, ETH, BNB, SOL, XRP.
- Venues: Binance, OKX, Bybit, Gate, KuCoin.
- Resolution: exact completed one-minute candles ending at the UTC-hour epoch boundary.
- Quorum: at least three complete atomic five-asset venue vectors.
- Return scale: integer parts per billion with a floor median.
- Objectives: HIGH and LOW, with deterministic tie/refund behavior.
- Stakes: deployment-pinned minimum and per-wallet maximum.
- Fee: fixed 200 basis points of each losing pool when parimutuel settlement applies.
- Timeout: permissionless principal refund after 24 hours if consensus resolution never finalizes.

## V8-only testnet cutover

V6 and V7 source files and old deployment manifests are retained only as immutable audit history.
They are not product routes, fallback deployments, active keepers, or claim surfaces. No V7 balance
or claim is migrated or reproduced: those were test tokens, and the V8 cutover intentionally starts
with fresh Bradbury state.
